把车联网安全「拆开看」

本库把 delikely.eu.org 上散落的车联网 / 固件 / IoT 实践文章，重组成一条可读路径： 先看攻击面 → 再学怎么挖 → 最后对照怎么防。 适合安全测试、固件分析与主机厂/供应商安全工程入门。

TBOX / 车机 / ECU 固件提取 UDS / OTA 协议栈 整车渗透 防御加固

1. 攻击面地图（先建立全局）

智能网联汽车不是「一台手机 + 四个轮子」，而是多层系统叠加。挖洞前先认清入口：

云端 / TSP / OTA 手机 App TBOX / OCU 车机 IVI 诊断 OBD/UDS 充电桩 / EVSE Wi-Fi / BT / 蜂窝 CAN / Eth 总线 USB / 外设 ECU 固件 / MCU

用一句话理解各层

  • 云与 App：远程控车、账号、OTA 分发——常见 Web/API/业务逻辑洞。
  • TBOX（车载通信单元）：蜂窝上网、定位、与 TSP 通信的「车外网关」，权限高、影响面大。
  • 车机：Android/QNX 等，多媒体与人机交互；USB、应用安装、ADB 常是突破口。
  • 诊断与刷写：UDS/OBD 可读写 ECU；Seed-Key 与刷写链是经典战场。
  • 总线：拿到一域权限后，可能横向到其他 ECU。
博客中对大众 OCU/TBOX、充电桩、整车渗透等的拆解，本质都是在这些面上「找入口 → 提权 → 影响车辆或数据」。

2. 漏洞挖掘：整车渗透怎么做

参考 整车渗透测试实践 ，把流程压缩成「可执行的 10 步」：

  1. 前期沟通：测零部件还是整车？有无台架？能否拆硬件？开发版还是量产？目标是合规报告还是深挖漏洞。
  2. 前期情报：平台共用模块多，可用 OSINT 找企标、算法库、DID、车友玩法（任意安装等）。
  3. 环境验收：版本是否完整、网络能否上、App 是否绑车——环境坑会吃掉大量工时。
  4. 信息收集：芯片、丝印、调试口、开放端口、进程、OTA 业务流；用表 + 架构图共享。
  5. 威胁建模：资产 → 威胁场景 → 攻击路径 → 排优先级与时间盒。
  6. 漏洞挖掘：静态（固件/二进制/配置）+ 动态（协议/业务/Fuzz）。
  7. 漏洞验证：PoC、Nday、服务洞、业务洞分开验证，避免「看似能打其实不行」。
  8. 后渗透：shell → 扫其他 ECU/服务 → 隧道 → 固件残留 → 拼攻击链与录屏。
  9. 报告：合规清单 + 漏洞细节 + 过程证据。
  10. 回归：补丁是否可绕过、是否修全。
ISO 21434 / WP.29 R155 把渗透测试列为验证手段之一；实战里扫描、Fuzz 通常嵌在渗透流程中，而不是互相替代。

2.1 灰盒 / 黑盒：攻击方式与逻辑（细拆）

据 整车渗透测试实践 ：内部团队可黑/白/灰三法；外部项目多为黑盒，灰盒通常只有规范/架构的一小部分。 完整对照表见 knowledge/black-gray-box.md。

三种盒子差在「信息」

方法手里有什么核心打法
白盒 源码、二进制、完整设计文档 审计为主；主机厂也不一定拥有全部供应商源码
黑盒 几乎无内部资料 逆向补齐情报，再打。必拿三类：IPC/RPC、私有协议字段、OTA 分发方式
灰盒 算法 / 架构 / 数据结构；外部多为安全设计规范 按文档建用例 → 动态验证「文档 vs 实现」差异

黑盒逻辑：把黑盒「变成自己的灰盒」

  1. 找入口：USB / OBD / 无线 / App / 公网桩 / 调试口等外部可见面。
  2. 补情报：OSINT（模块化平台复用、企标、27 算法、DID、车友玩法）+ 硬件拆解 + 固件提取 + 抓包。
  3. 建模型：服务拓扑、协议字段、信任边界；逆向 IPC、私有协议、OTA 链。
  4. 钻半开缝：能 push 不能 shell、挂载可穿越、弱 Seed-Key、未授权升级 API…
  5. 后渗透：扫 ECU、隧道、固件残留、拼攻击链取证。

黑盒：按面拆的攻击逻辑

硬件 / 固件

SOP Flash 测夹、MCU SWD 夹脚、ECU Bench/BDM/Boot/OBD、大映像分区挂载 → 静态挖密钥、算法、下载地址、CVE。

TBOX / OCU

蜂窝降级、Wi-Fi 弱密、APN 进内网、总线横移、OTA 截包/验签、调试口、弱口令服务、全 root。

ADB「半授权」

shell 要密码但 push/pull 可用 → 写 hotplug/uevent_helper → 触发 uevent → 高权限服务。详见 Tesla TCU 复现文。

车机 U 盘

udev 用 LABEL 拼挂载点且未过滤 ../ → 穿越劫持系统路径 → 挂载后调用被劫持命令。

UDS / 刷写

逆向 Seed2Key、默认常量、弱/固定种子、Reset 绕延时、34/36 无认证、CAN 旁听明文固件、应用层绕过诊断认证。

OTA

平台洞 / 测试包 / 明文 / 逆向地址拿包 → 验签绕过或反推他 ECU 升级链；策略缺陷可致可用性事故。

充电桩

选「公网 + 固件可得」→ 硬编码、未授权后台、升级命令注入、免费充电 API；控制器供应链影响多品牌。

业务 / 合规

对照 TBOX 业务（远程控车、eCall、监管上报）做滥用；TBOX 抓包查境外 IP（跨境条款）。

灰盒逻辑：文档怎么变成用例

  • 文档驱动：规范写「应验签 / 应关 ADB」→ 列验证用例直接打勾或打叉。
  • 差异驱动：文档有签名、实现找不到验签路径 → 优先深挖。
  • 算法已知：不必从零逆向 27，专注种子随机性、失败锁定、会话绑定、Reset 旁路。
  • 架构已知：按 EE/域图排横向优先级，而不是全车盲扫。
  • 仍要黑盒手段：文档会过时、供应商会偏离；灰盒缩小搜索空间，黑盒验证与补洞。

同一目标：黑盒 vs 灰盒两条路

目标黑盒路径灰盒路径
破 27 提固件 → 逆向算法/常量 按算法文档实现 → 测随机性与锁定
打 OTA 截流量 / 逆向客户端 按设计构造乱序、非法包、降级
拿 TBOX shell 服务扫描、ADB 半开、硬件口 对照调试/账号基线逐项验
车机提权 U 盘/USB/任意安装链 对照外设与签名安装策略
横移 ECU 落点后扫总线与服务 按架构图选高价值域与网关

五条常见攻击链（模板）

  1. 外设 → 车机 → 域内：挂载/USB 策略缺陷 → shell → 邻接 ECU / 隧道。
  2. 调试半开 → 通信单元：ADB/串口缝 → TBOX 高权限 → OTA / APN / CAN。
  3. 固件 → 诊断 → 刷写：提固件得算法 → 弱 27 → 非法刷写或旁听明文包。
  4. 公网桩 → 供应链：暴露面 + 固件 → 控制器级洞影响多品牌。
  5. 业务合规：功能全开抓包 → 出境 IP / 敏感数据路径。
以上为授权测试方法论摘要，不提供可直接套用的利用脚本。 原文入口： ADB 复现 · U 盘穿越 · UDS · 充电桩 · OCU

3. 固件与硬件：挖洞的「弹药库」

没有固件，很多漏洞只能停在猜测。博客反复强调的路径：

3.1 怎么拿到固件

  • 免拆读 Flash：SOP 封装 SPI Flash 用测夹 + 编程器读取（汽车场景常用）。
  • MCU 内置 Flash：SWD/JTAG 调试口；口被隐藏时尝试夹针脚；读保护未开会大幅降低门槛。
  • 诊断/刷写工具：动力域常用 KTAG/KESS 等（需合法授权场景）；OBD 读写与解锁流程。
  • OTA / 升级包：平台漏洞、测试包泄露、明文传输、逆向下载地址。
  • 磁盘镜像：如 Tesla 车机，从映像中抠出文件系统再分析。

3.2 拿到固件后挖什么

  • 硬编码密钥、证书、Seed-Key 常量、云端 URL
  • 危险函数 / 命令拼接 / 缓冲区问题
  • 开放服务配置、默认口令、过时组件 CVE
  • 升级验签逻辑是否可跳过
  • 与其他模块的信任关系（是否盲目信任总线消息）
硬件入口本身也是洞：未保护的串口、ADB、USB、JTAG，往往比「0day」更快拿到第一落点。

4. 诊断、刷写与 OTA（协议向挖洞）

4.1 UDS 刷写（高频考点）

详见 UDS 刷写 。测试时重点看：

  • 安全访问（0x27）：种子是否随机、算法是否可逆向、常量是否硬编码、能否故障注入绕过。
  • 请求下载 / 传输数据（0x34/0x36）：是否未认证就可刷；传输是否加密（CAN 可被嗅探）。
  • 刷写前置条件：车速、供电、档位等互锁是否可被欺骗。
  • 格式：S19 / HEX / BIN / VBF 等，影响分析与篡改方式。

4.2 OTA 业务链

  • 云端平台漏洞 → 包泄露 / 非法推送
  • 车端验签绕过 → 刷入恶意固件
  • 策略不合理 → 升级过程影响可用性与安全（停车无法下车等极端案例需纳入风险意识）

4.3 无线与外设

  • 蜂窝降级、GNSS 欺骗、Wi-Fi/BT 协议栈
  • USB 目录穿越到 shell（车机经典路径）
  • 充电桩：外网暴露 + 工控/支付/控制逻辑交叉

4.5 协议栈深入分析思路

完整细拆见 knowledge/protocol-stack.md 。核心口诀：先拓扑，再字典，后字段。

  1. 定接入点：端子 / OBD / 车机网卡 / TBOX 无线。
  2. 画域与网关：Diag、TBUS、底盘、车身、信息、能量等谁同域、谁转发。
  3. 收协议字典：DBC / LDF / ODX / ARXML / 企标 / 固件字符串。
  4. 分层还原：总线帧 → ISO-TP/DoIP → UDS/SOME/IP/私有 RPC → 业务指令。
  5. 负向用例：跳步、重放、越权 DID、畸形长度、错误来源；静动对照找实现差异。

车内

CAN/LIN 信号信任；UDS 27→34/36 状态机；DoIP 路由激活；SOME/IP 服务发现与鉴权。

车外

TBOX↔云私有协议、OTA 分发与验签、App/TSP API、充电桩管理面与车桩交叉。

黑盒必补三类情报中的「IPC/RPC」「私有协议字段」都落在这一层；有字典时优先差异分析（文档有线上无 / 线上有文档无）。

5. 车联网常见漏洞类型（细数）

类型 表现 常见落点
认证绕过 ADB/登录/接口无需有效凭证 车机、TBOX、云 API、充电桩 Web
弱口令 / 默认口令 SSH/Telnet/后台可进 TBOX、摄像头、路由器类组件
命令注入 / 内存破坏 可控输入进 system/溢出 CGI、诊断代理、升级脚本
路径穿越 USB/文件接口写到系统路径 车机媒体/升级目录
不安全刷写 无认证、弱 Seed-Key、明文包 UDS、售后工具、OTA
供应链 / 组件洞 已知 CVE 未修 Dnsmasq 等开源组件、第三方 SDK
权限模型缺陷 全 root、域间无隔离 Linux/Android/QNX 服务
敏感数据泄露 密钥、日志、跨境传输 固件、云同步、日志通道
总线信任滥用 伪造报文驱动执行器 CAN/车载以太（需先有入口）

6. 防御知识点拆解

防御不是「上一套防火墙就结束」，而是与攻击面一一咬合：

安全启动与信任链

Boot → 系统 → App/固件包层层验签。即使刷写认证被破，被篡改镜像也应拒绝启动。

调试与量产差异

量产关闭 ADB/JTAG/串口或加认证；读保护与熔丝策略按阶段切换。

诊断与刷写加固

真随机种子、失败锁定、敏感服务强制安全访问；优先非对称方案；密钥放安全存储/HSM。

通信与 OTA

加密+完整下载；平台最小暴露；升级互锁与可用性策略；异常监测与回滚。

系统硬化

非 root 运行、沙箱、组件补丁基线、关闭明文管理口、私有协议加密。

组织与流程

威胁建模进开发流程；渗透+回归；漏洞定级（如 GB/T 相关实践）；供应商安全要求进合同。

7. 挖洞 ↔ 防御对照（精简表）

你挖到什么 对方该怎么防
调试口直通 shell 量产关闭/认证；物理不可达
Flash 一夹就出固件 读保护 + 密文关键数据
Seed-Key 可算 / 固定种子 真随机 + 抗逆向 + 锁定策略
未认证 34/36 刷写 强制安全访问与互锁
OTA 包可伪造 安全启动 + 不可跳过验签
USB 穿越提权 路径规范化 + 签名应用白名单
弱口令远程管理 禁用/证书认证 + 监控
拿到车机后横移 ECU 网关策略、域隔离、报文过滤

9. 建议学习路径

  1. 建立地图：EE 架构、模块化平台、TBOX/车机分工（先读博客「基础知识」系列）。
  2. 学会拿固件：免拆 Flash / MCU / 镜像提取，再做文件系统与字符串巡检。
  3. 协议分层：端子拓扑 → DBC/ODX 字典 → UDS/DoIP/SOME/IP（见 protocol-stack.md）。
  4. 跟一条完整渗透：按整车渗透 10 步走通一个台架或零部件。
  5. 专攻一条链：UDS 刷写 或 OTA 或 USB/车机提权，挖深到可复现。
  6. 反过来写防御：每发现一类洞，补一条设计/测试要求进检查表。
