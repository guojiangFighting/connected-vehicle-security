# 灰盒 / 黑盒攻击方式与逻辑（授权测试语境）

来源总站：[Delikely's Blog](https://delikely.eu.org/)  
本文把博客中散落的车联网实践，按**测试身份（黑盒/灰盒）**与**攻击逻辑**重组，便于本地查阅。细节以原文为准；仅用于已获书面授权的安全评估。

协议分层（端子 → 字典 → UDS/DoIP/SOME/IP）见 [`protocol-stack.md`](protocol-stack.md)。

---

## 1. 三种盒子：信息差决定打法

据 [整车渗透测试实践](https://delikely.eu.org/2023/10/10/pentest-workflow-for-automotive/)：

| 方法 | 你手里有什么 | 典型打法 | 谁常做 |
|------|--------------|----------|--------|
| **白盒** | 源码、二进制、完整设计文档 | 审计、文档审查为主 | 多为主机厂内部；外部很少 |
| **黑盒** | 几乎无内部资料 | **逆向拿情报** → 再打 | 外部项目主流 |
| **灰盒** | 部分设计文档（算法、架构、数据结构等） | **按文档建用例**，再结合动态验证 | 内部多；外部多为「安全设计规范」级 |

**外部团队的现实**：多数项目是黑盒；灰盒往往只有一小部分（规范/架构图），不会有完整源码。

黑盒要自己逆向出来的三类「关键情报」（原文明确点名）：

1. **IPC/RPC 通信方式**（进程间/组件间怎么说话）
2. **私有协议字段定义**
3. **OTA 升级包分发方式**

## 2. 黑盒攻击逻辑总图

```text
外部可见入口（USB/OBD/无线/App/公网桩/调试口）
        │
        ▼
情报获取（OSINT / 硬件拆解 / 固件提取 / 流量）
        │
        ▼
建立内部模型（服务拓扑、协议字段、信任边界）
        │
        ▼
找「半开」的权限缝（可 push 不可 shell、可挂载可穿越、弱 Seed-Key…）
        │
        ▼
第一落点 → 后渗透（扫 ECU、隧道、固件残留、拼攻击链）
```

黑盒的核心不是「盲目扫端口」，而是：**用逆向把黑盒变成自己的灰盒**。

## 3. 黑盒：按攻击面拆解的方式与逻辑

### 3.1 OSINT / 平台复用（零接触情报）

逻辑（[模块化平台](https://delikely.eu.org/2021/07/25/Automotive-Modular-Platform/) + 渗透文）：

- 主机厂用模块化平台 → 新车常带旧车影子。
- 客户给的资料不足时，用公开情报补：企标、代码/27 算法泄露、DID、车友「任意安装」等玩法。

**攻击逻辑**：先缩小「未知」范围，再决定硬件拆还是协议打。

### 3.2 硬件与固件提取（把黑盒打开）

来源：[免拆提取固件](https://delikely.eu.org/2021/01/11/%E5%85%8D%E6%8B%86%E8%8A%AF%E7%89%87%E6%8F%90%E5%8F%96%E5%9B%BA%E4%BB%B6/)、[汽车中的应用](https://delikely.eu.org/2021/01/30/%E5%85%8D%E6%8B%86%E8%8A%AF%E7%89%87%E6%8F%90%E5%8F%96%E5%9B%BA%E4%BB%B6%E5%9C%A8%E6%B1%BD%E8%BD%A6%E4%B8%AD%E7%9A%84%E5%BA%94%E7%94%A8/)、[Tesla 磁盘映像](https://delikely.eu.org/2021/03/10/Tesla%E8%BD%A6%E6%9C%BA%E5%9B%BA%E4%BB%B6%E5%88%86%E6%9E%90%E7%AC%AC%E4%B8%80%E6%AD%A5%EF%BC%9A%E4%BB%8E%E7%A3%81%E7%9B%98%E6%98%A0%E5%83%8F%E4%B8%AD%E6%8F%90%E5%8F%96%E6%96%87%E4%BB%B6%E7%B3%BB%E7%BB%9F/)

| 方式 | 逻辑 | 黑盒价值 |
|------|------|----------|
| SOP Flash 测夹 + flashrom | 针脚外露 → 直接读 SPI | 拿到文件系统/密钥/URL |
| MCU SWD/JTAG 夹针脚 | 调试口未引出则夹脚；验证 CRP/RDP | 内置 Flash 程序与算法 |
| ECU 刷写工具（Bench/BDM/Boot/OBD） | 动力域成熟读写链 | 标定/程序备份与对比 |
| 大容量映像分区挂载 | fdisk/losetup/LVM 拆分区 | 车机完整根文件系统 |

**后续静态挖洞逻辑**：硬编码密钥、Seed-Key 常量、OTA 下载地址、危险函数、默认口令、过时组件 CVE。

### 3.3 TBOX / OCU：通信网关黑盒路径

来源：[TBOX 功能](https://delikely.eu.org/2021/08/15/TBOX-Main-Function/)、[大众 OCU](https://delikely.eu.org/2021/09/29/VW-OCU/)

黑盒观察面 → 攻击逻辑：

| 观察面 | 攻击逻辑 |
|--------|----------|
| 蜂窝 / Wi-Fi / BT / GNSS | 降级、弱初始密码、协议栈、定位欺骗（多模则威胁降） |
| 内网 APN | 经 TBOX 进企业内网，内网防护弱则横向 |
| 总线（CAN/Eth） | 拿 TBOX 后伪造/转发报文打其他 ECU |
| OTA 经 OCU↔TSP | 流量/程序逆向拿包 → 验签绕过或分析他 ECU 升级链 |
| 调试口（串口/ADB/USB/JTAG） | 量产未关 = 最快第一落点 |
| 开放服务 | SSH/Telnet 弱口令、私有服务明文敏感数据 |
| 权限模型 | 全 root → 一落点即高权限 |

**业务黑盒**（功能即攻击面）：网络接入、OTA、远程控车、定位、eCall、远程诊断、国标监管上报（GB/T 32960）——每条业务都对应「伪造指令 / 窃听 / 篡改 / 可用性破坏」四类风险。

### 3.4 ADB「半授权」缝：认证绕过逻辑

来源：[Tesla TCU ADB 认证绕过复现](https://delikely.eu.org/2025/12/27/Tesla-TCU-ADB-Bypass-Reproduction/)

**现象（黑盒可观测）**：`adb shell` 要密码，但 `adb push/pull` 未授权可用。

**攻击逻辑（概念层）**：

1. 分区只读 → 简单覆盖自启文件往往失败。
2. 若内核仍暴露 `uevent_helper` / `hotplug`，且 adb 侧具备 root 写权限，则可把「帮助程序路径」指到可写脚本。
3. 再触发 uevent（USB 热插拔或写 sysfs uevent）→ 内核 fork 执行脚本 → 拉起高权限服务 → 交互 shell。

**同类历史路径**：文件覆盖、Seed/算法逆向拿 ADB 口令——同一目标（shell），不同缝。

### 3.5 车机外设：U 盘挂载路径穿越逻辑

来源：[U盘目录穿越获取车机 SHELL](https://delikely.eu.org/2021/06/04/U%E7%9B%98%E7%9B%AE%E5%BD%95%E7%A9%BF%E8%B6%8A%E8%8E%B7%E5%8F%96%E8%BD%A6%E6%9C%BASHELL/)

**逻辑链**：

1. udev 用脚本按 UUID/LABEL 拼挂载点。
2. LABEL 可控且未过滤 `../` → 挂载点可穿越到系统目录。
3. 挂载后脚本再调用 `logger` 等路径 → 劫持系统二进制 → 任意命令执行。

黑盒要点：不必先有 shell；**外设策略 + 挂载脚本**本身就是入口。

### 3.6 诊断 / UDS 刷写黑盒逻辑

来源：[UDS 刷写](https://delikely.eu.org/2023/05/01/UDS-flash/)

黑盒侧可见：OBD/DoIP 上的会话切换与 27/34/36 交互。

| 威胁点 | 攻击逻辑 |
|--------|----------|
| Seed2Key 可逆 | 逆向 ECU/诊断仪得到算法与安全常量 |
| 默认/共用常量 | 跨 ECU/跨车型复用同一常量 |
| 种子弱/固定/可预测 | 爆破或预测 Key |
| 认证延时可绕 | Reset、低权限穿插清计数器等 |
| 34/36 无认证 | 跳过 27 直接刷 |
| CAN 明文下载 | 旁听总线截固件 |
| 应用层远程诊断 | 绕过诊断安全访问直接调敏感功能 |
| 刷写前提不健全 | 行驶中停通讯/擦除 → 安全与可用性风险 |

### 3.7 OTA 黑盒逻辑

来源：OCU 威胁章节 + TBOX OTA 功能

```text
找包（平台洞 / 测试包泄露 / 售后 / 明文截取 / 逆向下载地址）
  → 分析包结构与验签
  → 验签可绕则恶意刷写
  → 或从包反推其他 ECU 升级逻辑
```

另：升级策略不合理 → **可用性/人身安全**类问题（非传统「提权」但属安全范围）。

### 3.8 充电桩：公网黑盒 + 供应链

来源：[充电桩漏洞挖掘实践](https://delikely.eu.org/2022/04/29/chargebox-vuln-hunter-garo-and-bender/)

**选靶逻辑**：公网可访问 + 固件可获取 → 适合远程黑盒。

| 模式 | 逻辑 |
|------|------|
| 固件静态 | 硬编码 SSH、明文 Web 账密、隐藏后台路径指纹 |
| Web 未授权 | 无认证管理页、未授权业务 API（如免费充电） |
| 升级接口 | `downloadAndUpdate` 类参数进命令 → 未授权命令注入 |
| 供应链 | 同一充电控制器（如 CC612）影响多品牌；开源组件（log4j）需验证 |

### 3.9 跨境 / 业务合规向黑盒

来源：[跨境传输检测](https://delikely.eu.org/2023/05/14/cross-border-check/)

逻辑：在 TBOX 等抓包 → 提公网 IP → 归属地判定 → 是否直接出境。  
属「业务与合规验证」，常与渗透并行。

### 3.10 拿到落点后的黑盒后渗透逻辑

来源：整车渗透「后渗透」

- 车机/TBOX shell → 扫其他 ECU 与开放服务  
- 内网穿透建立稳定通道  
- 找固件残留继续横向  
- 拼攻击链并录屏取证  

车机侧辅助：在隔离网段用本地 Python/Scapy 测 SOME/IP 等（[车机跑 Python](https://delikely.eu.org/2023/11/16/pydroid/)）——属于**测试能力建设**，不是漏洞本身。

## 4. 灰盒攻击逻辑：文档怎么变成用例

灰盒输入（渗透文）：算法说明、系统架构、内部数据结构；外部团队常见是**安全设计规范**。

### 4.1 灰盒比黑盒「快在哪」

| 你已有 | 可直接建的用例 | 仍需验证 |
|--------|----------------|----------|
| 架构图 / 域划分 | 信任边界、网关策略、横向路径优先级 | 实现是否与文档一致 |
| Seed2Key / 安全常量说明 | 安全访问强度评估、错误实现检查清单 | 种子随机性、延时、是否可 Reset 绕过 |
| OTA 流程与验签设计 | 跳步、重放、降级、回滚用例 | 车端实现是否可绕 |
| DID / 例程列表 | 敏感 DID 读写、刷写前提条件 | 实际未文档化的后门 DID |
| 接口清单（调试/USB/ADB） | 量产是否应关闭的基线对照 | 实车是否残留 |

### 4.2 灰盒典型逻辑（对照黑盒）

1. **文档驱动**：先按规范列「应满足」→ 再测「是否满足」（偏验证）。  
2. **差异驱动**：文档说有签名，固件里找不到验签路径 → 优先深挖。  
3. **常量/算法已知**：不必从零逆向 27，专注随机性、锁定、会话绑定等实现缺陷。  
4. **业务用例完整**：对照 TBOX 业务清单（远程控车、eCall、监管上报）逐项做滥用用例，补黑盒「时间不够挖业务」的短板。

### 4.3 灰盒仍做的「黑盒动作」

灰盒**不取消**逆向与动态打点：文档可能过时、供应商实现偏离、隐藏接口未写入规范。正确姿势是：**灰盒缩小搜索空间，黑盒手段验证与补洞**。

## 5. 黑盒 vs 灰盒：同一目标的两条路径

| 目标 | 黑盒路径 | 灰盒路径 |
|------|----------|----------|
| 破 27 安全访问 | 提固件 → 逆向 Seed2Key → 找常量 | 直接按算法文档实现 → 测种子/锁定/旁路 |
| 打 OTA | 截流量/逆向客户端找下载与验签 | 按 OTA 设计文档构造非法包与流程乱序 |
| 拿 TBOX shell | 扫服务、ADB 半授权、硬件调试口 | 对照调试接口基线与账号体系设计 |
| 车机提权 | U 盘/USB/任意安装等外设链 | 对照外设安全策略与签名安装规范 |
| 充电桩 | 公网指纹 + 固件下载 + Web/API | 有开发文档时（博客：友商文档帮大忙）加速找隐藏页与升级接口 |
| 横移 ECU | 落点后扫总线/服务 | 按 EE 架构图选高价值域与网关绕过点 |

## 6. 攻击链模板（授权测试用）

### 链 A：外设 → 车机 → 域内

外设策略缺陷 → 车机执行环境 → 扫描邻接 ECU / 隧道 → 影响扩大

### 链 B：调试半开 → 通信单元 → 云或总线

ADB/串口「半权限」→ TBOX/TCU 高权限 → OTA/APN/CAN

### 链 C：固件 → 诊断 → 刷写

提固件得算法/常量 → 弱 27 → 非法 34/36 或窃听明文刷写

### 链 D：公网桩 → 供应链

公网暴露 → 固件/后台 → 控制器级漏洞影响多品牌

### 链 E：业务合规

功能全开抓包 → 出境 IP / 敏感数据路径 → 合规与隐私风险
